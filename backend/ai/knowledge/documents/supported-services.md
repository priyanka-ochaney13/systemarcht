# SystemArcht supported services

SystemArcht Module 1 focuses on API Gateway, Lambda, EC2, RDS, DynamoDB, and S3. API Gateway handles HTTP ingress. Lambda is suited to event-driven or bursty workloads with automatic scaling and pay-per-use economics. EC2 is suited to steady, predictable, long-running workloads where capacity control can be more economical. DynamoDB provides scalable key-value access and serverless operations. RDS is for relational data and strong transactional constraints. S3 is the preferred service for large unstructured objects such as photos and files; presigned URLs reduce API and compute load and lifecycle rules help optimize storage cost.

For memory-intensive EC2 workloads, evaluate memory-optimized R instances first because they provide more RAM per vCPU than general-purpose instances. A Graviton-based R instance can reduce price when the application and dependencies support ARM64. Choose the smallest instance that meets measured memory and CPU needs, then compare On-Demand with Savings Plans or Reserved Instances for steady usage. Burstable T instances are generally a poor fit for sustained memory-intensive workloads. Exact instance pricing depends on region, operating system, purchase model, and utilization, so the assistant should ask for those details before making a cost claim.
